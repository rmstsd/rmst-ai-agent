# 创建订单

1. 从请求中提取场景、起点、目的地、容器详情、优先级和机器人限制。
2. 如果场景缺失或存在歧义，请求用户提供。查询场景列表并选择一个已启用的场景。
3. 查询场景架构。将起点和目的地解析为准确的点位或货位名称；不要猜测。
4. 使用 [order-schema.md](../references/order-schema.md) 构建两步请求。
5. 如果请求使用 dry-run，则展示请求并停止。
6. 在调用 `POST /api/fleet/orders/create` 前，展示场景、起点、目的地、机器人约束和准确操作，并请求确认。
7. 仅在确认后提交。
8. 返回后端的 `orderId`，并说明订单已接受，但不一定已开始执行。
9. 当操作员询问分配或执行状态时，查询订单详情。
